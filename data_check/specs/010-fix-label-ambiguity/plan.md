# Implementation Plan: Fix Codebook Label Ambiguity

**Branch**: `010-fix-label-ambiguity` | **Date**: 2026-03-17 | **Spec**: [spec.md](spec.md)

## Summary

Add a two-tier label-conflict resolution step inside `match_column_labels()` in `helper.R`. Before flagging `conflicting_definition`, the pipeline first tries rule-based label normalisation (free), then an LLM equivalence check (1 batch call per paper). Semantically equivalent labels are merged into a single canonical label with `label_method = "merged_rules"` or `"merged_llm"`. Genuinely conflicting labels continue to emit `conflicting_definition` unchanged.

The BIS misplaced-label report was investigated and found to be correct per source codebook — no code change required for that case.

## Phase 1 — Design

### Data Model

No new persistent entities. Changes to existing output columns only:

**`labels.csv` — `label_method` column** (additive enum extension)

| New value | Meaning |
|-----------|---------|
| `merged_rules` | Multiple candidate labels collapsed by rule-based normalisation; canonical = longest original string |
| `merged_llm` | Multiple candidate labels confirmed equivalent by LLM; canonical = LLM-chosen label |

All other columns (`label_status`, `label`, `codebook_variable`, `label_source`) unchanged in meaning.

**`label_status` for merged rows** = `"labelled"` (existing value; no schema change).

---

### Contracts (internal — no external interface)

`match_column_labels()` signature change (backward-compatible):

```r
# Before
match_column_labels(columns_df, codebook_vars_df, column_match_prompt = NULL)

# After
match_column_labels(columns_df, codebook_vars_df,
                    column_match_prompt = NULL,
                    label_merge_prompt  = NULL)
```

When `label_merge_prompt = NULL` (default): LLM merge tier is skipped. Rule-based tier always runs (zero cost). Existing callers unchanged.

### New helper: `normalize_label(x)`

Location: `helper.R`, near `normalize_varname()`.

Algorithm:
1. `tolower(x)`
2. Strip possessive apostrophes: `gsub("'s|'s", "", x)`
3. Strip all non-alphanumeric except spaces: `gsub("[^a-z0-9 ]", " ", x)`
4. Strip trailing "s" from words ≥5 chars (handles participants→participant): use word-split approach
5. Collapse whitespace: `gsub("\\s+", " ", trimws(x))`

Examples:
- "Participants' age" → "participant age"
- "Participant age" → "participant age" ✓ (merge)
- "Qualtrics assigned participant ID" → "qualtrics assigned participant id"
- "Qualtrics participant ID" → "qualtrics participant id" ✗ (different → escalate to LLM)

### New helper: `.resolve_label_conflicts(labels, col_name, merge_prompt)`

Location: `helper.R`, called from inside `match_column_labels()`.

Inputs:
- `labels`: character vector of distinct labels for one column
- `col_name`: original column name (for LLM prompt body)
- `merge_prompt`: LLM system prompt or NULL

Returns: list `(resolved = TRUE/FALSE, canonical = character(1), method = "merged_rules"|"merged_llm"|NULL)`

Logic:
```
1. Normalize all labels with normalize_label()
2. If length(unique(normalized)) == 1:
   → resolved=TRUE, canonical=labels[nchar(labels)==max(nchar(labels))][1], method="merged_rules"
3. Else if merge_prompt is NULL:
   → resolved=FALSE
4. Else: add column to batch for LLM call (deferred — see below)
```

---

### LLM batch design

Rather than calling `.resolve_label_conflicts()` per-column, the LLM tier is batched at the `match_column_labels()` level:

1. After the rule-based pass, collect all columns still flagged `conflicting_definition`.
2. Build a single prompt body listing each column and its candidate labels.
3. One `llm()` call with `LABEL_MERGE_PROMPT`.
4. Parse response: for each `{column, equivalent, canonical}` entry, apply merge if `equivalent=TRUE`.
5. Columns not in the LLM response remain `conflicting_definition`.

**`LABEL_MERGE_PROMPT`** (to be added to `2_codebook_label.R`):

```
You are reviewing whether multiple label definitions for the same variable in a psychology
research dataset are semantically equivalent.

You will receive a list of variables, each with multiple candidate label definitions.
Return a JSON array — one object per variable.
Each object: {"column": "<column_name>", "equivalent": true/false, "canonical": "<best label>"}

Rules:
- equivalent: true if all listed labels describe the same construct (synonyms, different phrasings, or one is a value-coding notation for the same concept as a semantic label)
- canonical: if equivalent=true, return the most human-readable, informative label; if equivalent=false, return null
- Do NOT mark as equivalent if labels describe genuinely different constructs or measurement scales
- Output ONLY the JSON array. No notes, no text outside the array.
```

### Execution flow (updated `match_column_labels()`)

```
existing rule-based loop (unchanged)
  → produces: labelled, conflicting_definition, unlabelled, ambiguous_experiment rows

[NEW] Rule-based merge pass:
  for each conflicting_definition row:
    normalize all its candidate labels
    if all normalized == same string: set to labelled, method="merged_rules", canonical=longest

[NEW] LLM merge pass (only if label_merge_prompt != NULL and any conflicting remain):
  batch all remaining conflicting columns into one LLM call
  parse response
  for each equivalent=TRUE result: set to labelled, method="merged_llm", canonical=llm_canonical

existing LLM column-matching pass (unchanged, runs on unlabelled rows)
```
