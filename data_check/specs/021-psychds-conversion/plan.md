# Implementation Plan: PsychDS Conversion

**Branch**: `021-psychds-conversion` | **Date**: 2026-03-25 | **Spec**: `specs/021-psychds-conversion/spec.md`
**Input**: Feature specification from `/specs/021-psychds-conversion/spec.md`

## Summary

Convert metacheck-datacheck pipeline outputs (`structure.csv`, `columns.csv`, `labels.csv`, `codebook_coverage.csv`) into PsychDS-compliant dataset directories under `psychds/<paper_id>/`. Produces `dataset_description.json` (Schema.org JSON-LD), `*_data.csv` (UTF-8), `*_data.json` sidecars, `provenance.json`, and optionally `documentation/txt/` plaintext copies of `doc`/`codebook` files.

**US6 addition (2026-03-25)**: For `doc` and `codebook` type files with text-extractable formats (PDF, DOCX, RTF), write a `.txt` copy to `documentation/txt/`. Original files are never modified. Image-only PDFs and extraction failures are skipped and recorded in `provenance.json`.

## Key Design Decisions

See `research.md` for full rationale. Summary:

1. `xml2` for GROBID TEI XML (already installed, namespace-strip XPath)
2. `jsonlite::toJSON(auto_unbox=TRUE)` for JSON-LD (scalar values unboxed)
3. Full data read (`read_full_data`) without row limit — 500 MB guard replaces row limit
4. Crash-resilient summary: append-after-each-paper pattern (Constitution I)
5. Study detection: `unique(structure$group[structure$type == "data"])`
6. `pipeline_failed`/`no_data_files` error codes (Constitution V)
7. `apply_ground_truth()` + `sanitise_keyword_value()` in `helper.R` (Constitution IV)
8. `extract_plain_text()` in `helper.R` — reuses pdftools/officer/RTF patterns from codebook labelling; no new packages
